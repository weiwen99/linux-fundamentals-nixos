# 文风规范

本书的目标读者是零基础学习者，但教材本身按技术文档的语体写：陈述事实、给出步骤、说明原因。不模拟对话，不制造情绪，不替读者预设感受。

## 标题

- 标题是名词短语，不是句子，也不是问句。
- 反例：`这台机器在做什么`、`为什么要用 NixOS`、`怎么读这本书`
- 正例：`计算机的层次`、`选用 NixOS 的理由`、`阅读指南`
- 表格表头同此规则：`适合谁` → `适用对象`，`怎么触发` → `触发方式`。

## 人称

- 正文用第三人称或省略主语。
- 不用"你"作为叙述对象。需要指示操作时用祈使句：`打开终端`、`输入下面一行`。
- 不写"你会发现""你会看到""你需要记住"。直接说结论，或者直接给命令。
- "我们"只用于表示作者与读者共同执行的推演，例如数学推导；技术步骤不用。

## 句式

- 不用"不是 A，而是 B"的对偶。直接陈述 B，必要时另起一句说明 A 的局限。
- 破折号不用于追加解释。用冒号、句号或从句。
- 不用格言式短句收尾。段落结束在一句完整的事实或判断上，不落在"命令会过时，层次不会"这类对仗句上。
- 单句以 20 至 30 字为宜。低于 10 字的短句连续出现三句以上，读起来是口语提词，不是书面语。

## 元话语

以下表达一律删除，除非它承载具体信息：

- `这一章只做一件事`
- `值得记住的是`
- `说到底`、`归根结底`
- `其实`、`只是`（作语气词时）
- `真正重要的是`
- `一句话`
- `先说明一点`

需要交代章节目标时，用一句陈述：`本章说明 X 与 Y 的关系`，不加修饰。

## 口语词

技术写作允许工程行话（`跑通`、`卡住`、`报错`、`撞上 404`），不允许情绪化口语：

- 禁用：`折腾`、`翻车`、`踩坑`、`救命`、`别慌`、`顺手`、`搞定`、`一劳永逸`
- 慎用：`直接`、`就是`、`才`（强调语气）

## 具体化

- `很多`、`一些`、`若干` 换成数量、版本号或删掉。
- 举例必须能对应到一条可执行的命令或一个可观察的结果。

## 结构

- 每章依次为：导语（一句）、若干小节、练习、检查点。
- 不在每节末尾加小结句，不在段末加升华句。
- 提示框只承载三类内容：需要提示的危险、与主线无关但有用的背景、Unix 传统的由来。不用提示框做"金句展示"。

## 代码

代码块按格式化器的输出排。文风规则只管正文，不管代码块。规则与检查方法见 `docs/code-style.md`。
