# 代码规范

Nix 代码块由格式化器生成。终端会话块与纯文本块不套格式化器，只做空白清理。原因有两条：读者会照着书里的样子写自己的文件；手排的代码在改动一处以后，对齐会逐处失效。

## 规则

1. Nix 代码块（`nixcode`）与 `nixfmt --strict --width=82` 的输出逐字节一致。
2. 多行结构的收尾括号单独起行，缩进与开启该结构的语句所在行相同：

   ```nix
   services.nginx = {
     enable = true;
   };
   ```

   不允许把 `};` 缩进到内层，也不允许把收尾括号留在上一行末尾。
3. 两个及以上元素的列表一项一行。这条由格式化器执行，作者不手工合并成一行，也不手工拆开单元素列表。
4. 单行不超过 83 列，全角字符按两列计。代码框内宽 screen 433pt、print 428pt，等宽字体每字符 5.13pt，两种 A4 版式分别容 84 与 83 列，取 83。nixfmt 的 `width` 不含行首缩进，参数取 82。格式化器拆不开的长字符串与长标识符由作者改写；检查会拦下超限的行。窄版式放不下，由 minted 折行，见 `docs/build.md`。
5. 注释与代码之间只留一个空格。格式化器不会为了对齐而补空格。
6. 终端会话块（`shellsession`）与纯文本块（`textcode`）保留提示符与输出，不做自动重排；制表符换两个空格，去掉行尾空白与块尾空行。命令过长时用 `\` 续行，缩进四格；长 URL 可以先赋给变量再引用；无法拆分的输出原样保留，由 minted 折行。

Nix 片段也适用这几条：只有绑定列表的块，工具会包一层属性集再排，排完去掉外层。书中没有完整文件上下文的小块因此与整文件保持同一套缩进。

## 格式化器

```sh
nix shell nixpkgs#nixfmt
nixfmt --strict --width=82 configuration.nix
```

`--strict` 让换行位置不受输入排版影响：同一段语义无论原本怎么换行，结果一致。不带 `--strict` 时格式化器会保留作者的部分换行选择，两个人的文件就排不出同一个样子。

## 检查

```sh
tools/code-format.py --check     # 列出不合规的块，非零退出
tools/code-format.py             # 就地重排
```

`build.sh` 在编译前跑一次 `--check`，不合规直接停下。列宽与括号对齐超出格式化器能改的范围时，工具只报告，需要手工处理，写模式同样以非零退出。工具用 `NIXFMT` 环境变量定位格式化器；构建脚本从 nixpkgs 解析，路径写入 `build/env.sh` 复用。nixpkgs 升级带来新版本、输出风格变化时，检查会报出来，按新输出重排一次即可。

## 不做的事

- 不为了对齐手工加空格：格式化器会把连续空格压成一个。
- 不为排版改写语义：`let`、`with`、`lib.mkIf` 放在哪里由作者决定，格式化器只决定换行与缩进。
- 不把多行结构压回一行来节省页数；页数由内容决定，不由排版技巧决定。
